# 改善案
## 進め方
1. 以下の順番に進め方を変える
    1. Step1：AIに生成してもらった後に以下の内容を洗い出しを行う
        → 理由「仕様書とソースコードの突合せの洗い出し」だけを最初に行って、ソースコードの修正を行っているが、それ以外の単純な実装ミス(不具合)、設計思想によっては動作確認できない状態が出来てしまうため
        - 仕様書とソースコードの突合せの洗い出し（異常系も含める）
        - 設計思想へのソースコードが適合しているかの洗い出し
    2. Step2：「仕様の曖昧な点」を確認する
        - Step1で洗い出した仕様書の不明な点を、以下のことを意識しながら質問文を作成する
            ・「前提の説明」「提案型」「はい/いいえで答えられる」ような文章を作成
            ・AIに採点してもらう
    3. Step3：ソースコードの修正と説明責任
        - 不要なコメントの削除/洗い出した内容の修正/設計思想に合わせてリファクタリング/なぜこの書き方なのか、後続の実装（拡張性）をどう考慮しているかをメモに残す
    4. Step4：セルフレビュー
